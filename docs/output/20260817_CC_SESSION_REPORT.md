## 2. Смена позиционирования — и опровергнутый ADR

Ревизия CD установила проверяемый факт: **мост pamola-core в BEST выведен
2026-06-14**.

```
best/src/best/operations/constants.py:3
  "The pamola-core bridge was retired 2026-06-14; every operation is now a native
   implementation"
  BRIDGED_OP_CODES = 0
```

`pamola-core` отсутствует в зависимостях BEST; от `_bridge.py` остались только
устаревшие `.pyc`.

**ADR-PC-02 «мост BEST — публичный контракт» был ложен в момент написания** —
я записал его через два месяца после вывода моста, взяв за факт имена каталогов
`_bridge_impl/`, которые видел раньше. Ошибка успела разойтись по системному
промпту, аргументу против polars и нескольким описаниям PR.

Заменён на **ADR-PC-05**: *BEST — управляемая система исполнения; CORE —
открытый инструментарий privacy engineering.* Практическое следствие жёсткое:
**ни одно решение в этом репозитории больше не может опираться на «от этого
зависит BEST»**, включая мои собственные прежние обоснования.

Вывод про polars при этом устоял, но на других основаниях: выигрыш локализован
в строковых операциях и вызван построчным `.apply`, а не pandas; трёх
механизмов параллелизма уже достаточно; и — новое — для библиотеки, чья ценность
в лёгком привычном `pip install`, pandas это то, чего ждёт внешний пользователь.

## 4. Что добавлено

### Singling-out — третий критерий EDPB

Портирован, а не написан. Сравнены три реализации, **лучшая оказалась не в
BEST**:

| Источник | Подход | Движок |
|---|---|---|
| `spikes/i_piper/roles/msu.py` | MSU + SUDA2 (Эллиот) + DIS-риск | **pandas**, clean-room, без GPL |
| `best/singling_out_attack_001` | worst-case sweep + baseline + Wilson CI | polars |
| `redteam/adapters/anon.py` | обёртка над ANON CORPUS | адаптер |

Взяты оба движка, потому что они отвечают на разные вопросы: sweep — «насколько
экспонирован набор», MSU/SUDA — «какие колонки в этом виноваты». Второе для
инструмента инженера ценнее (доля не говорит, что обобщать), первое держит число
сопоставимым с BEST, PMF и каталогом DSL.

Базовая линия независимых маргиналов взята из BEST и методологически
обязательна: таблица с несколькими колонками высокой кардинальности уникальна
почти по построению, поэтому риск — это **превышение** над базой, а не сама
доля. Считается разностью, не отношением: отношение неустойчиво при базе,
близкой к нулю, то есть ровно в интересном случае.

Проверено на таблице 2×2, считаемой вручную — шесть чисел из шести сошлись.

### `supports_batch`

Объявлен на `BaseOperation`, поэтому **все 42 операции отвечают на вопрос**
(19 True, 23 False) вместо того чтобы бросать `FeatureNotImplementedError` при
попытке. Пять операций честно объявлены непакетными: три подавления и две
разделения. Две последние нашлись только при обходе публичного API — просмотр
пакета `anonymization` их не показывал.

Контракт сознательно **сужен**, а не расширен: семантика пакетного подавления
записей спорна (батч не самодостаточен, когда операция удаляет строки), и
переход `False → True` позже совместим, а обратный — нет.

## 5. Что вскрылось, когда гейты перестали быть совещательными

Двенадцать настоящих дефектов, которые прятал advisory-линт.

**Самый содержательный** — `common/regex/patterns.py`: ключ
`\d{2}/\d{2}/\d{4}` объявлен дважды, с `%d/%m/%Y` и `%m/%d/%Y`. Словарный
литерал оставляет последний, поэтому DMY-трактовка была мертворождённой и
**все неоднозначные даты всегда разбирались как американские**. Шесть таких
ключей. Дубликаты убраны без переупорядочивания — поведение сохранено
побайтово, но выбор перестал быть невидимым. Какая конвенция верна по
умолчанию — вопрос продуктовый (TD-PC-17).

**Шесть тестов никогда не исполнялись.** Линт покрывал только `pamola_core/`;
расширение на `tests/` показало девять F811, а переопределённый тест не падает —
он молча не запускается. В паре из `test_kl_divergence.py` выживает менее
ценный: `:134` проверяет публичный `calculate_metric` и мёртв, `:244` проверяет
приватный хелпер и исполняется (TD-PC-15).

**Тесты чуть не отправили 125 МБ в публичный репозиторий.** Push отклонён
GitHub: `pamola_core/utils/resources/models/lid.176.bin` — модель fastText,
которую тест скачивает **в дерево пакета**. TD-PC-12 повышен до High; тесты
пишут в рабочее дерево 43 файла, `.gitignore` — затычка, лечение это `tmp_path`,
и оно же разблокирует `pytest -n auto`.

## 6. Визуализация — вопрос к обсуждению, не решение

Цифра, которая переворачивает интуицию. Вес в `site-packages`:

```
plotly      57.8 МБ        matplotlib   25.4 МБ
fontTools   15.7 МБ        PIL          15.0 МБ
seaborn      2.2 МБ        wordcloud 1.3 · venn 0.3 · kaleido 0.2
```

**Plotly вдвое тяжелее matplotlib.** «Только HTML-движки» само по себе пакет не
ужимает: экономит ~44 МБ и оставляет 58 МБ plotly. Честный вопрос другой —
**должна ли графика вообще быть в базовой установке**.

Контекст: подсистема — 13 612 строк (6.7 % кодовой базы), двойной бэкенд в
16 файлах из 20, **13 модулей из 20 не упомянуты ни одним тестом**, а в
публичный API экспортирована **одна** функция.

Три позиции, которые стоит развести:

1. **Ужать** — вся графика в extra `[viz]`. Тому, кто маскирует одну колонку,
   не нужны ни plotly, ни kaleido.
2. **Сделать полезнее** — один HTML-отчёт на `task_dir` вместо россыпи PNG.
   Возможно, вовсе без библиотек: inline SVG плюс таблицы дают самодостаточный
   файл на килобайты. Это ближе к тому, что делает CORE ценным — не «нарисуй
   гистограмму», а «покажи, что сделано с данными и с каким результатом».
3. **Убрать двойной бэкенд** — два пути при одном используемом; это половина
   причины, почему 13 модулей не покрыты.

Позиции 1 и 3 совместимы и почти бесспорны; 2 — продуктовая.

Предлагаемая мера успеха: `pip install pamola-core` без extras ставит < 300 МБ,
а `task_dir` содержит один отчёт, который можно показать аудитору не открывая
Python.

## 7. Методологическая заметка

Трижды за сессию вывод строился на правдоподобном, но непроверенном допущении.
Стоит записать не сами ошибки, а их общую форму — она переносится.

| Допущение | Реальность | Что поймало |
|---|---|---|
| «Мост BEST — контракт» | выведен 2026-06-14 | CD |
| «Удаление 8 зависимостей проверено: ноль ссылок» | ссылок ноль, но `uvicorn` приносил `python-dotenv`, `torch` — `filelock`; пакет перестал импортироваться | чистая venv, 170 ошибок сборки |
| «`op_base` обвалился 96 % → 59 %» | прочитан `.coverage` от частичного прогона | сверка с настоящим отчётом |

> Подсчёт ссылок отвечает на вопрос «кто это импортирует», а не «что это
> приносило с собой». Отчёт о покрытии отвечает на «что выполнилось в этом
> прогоне», а не «что есть в проекте».

Обе проверки стоили минут и обе меняли вывод. Это дешевле, чем звучит.

Отдельно, операционное: правка файлов репозитория через PowerShell
(`Get-Content -Raw` + `WriteAllText`) читает UTF-8 как cp1251 и записывает
мохибейк. Так были испорчены workflow-файлы и README — дважды, одним и тем же
способом.

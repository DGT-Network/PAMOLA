## 2. Что обсудить первым: визуализация

Val: «сделать более полезной, возможно вообще без matplotlib — только HTML
движки, но давай обсудим». **Не решай за него.** Ниже — факты для обсуждения.

### Что есть

| | |
|---|---|
| `utils/vis_helpers/` | 20 файлов, 11 492 строки |
| `utils/visualization.py` (фасад) | 2 120 строк |
| Итого | **13 612 строк = 6.7 % кодовой базы** |
| Двойной бэкенд plotly + matplotlib | 16 файлов из 20 |
| Не упомянуты ни одним тестом | **13 из 20** |
| Экспортировано в публичный API | **одна** функция, `visualize_distribution_df` |

Архитектура зрелая: реестр бэкендов (`registry.py`), темы (`theme.py`),
контекст (`context.py`), 17 типов графиков. Проблема не в том, что подсистема
слаба, а в том, что она **переразвита и недопроверена**.

### Факт, который переворачивает интуицию

Вес в `site-packages`:

```
plotly           57.8 МБ
matplotlib       25.4 МБ
fontTools        15.7 МБ      PIL   15.0 МБ
seaborn           2.2 МБ      wordcloud 1.3 · venn 0.3 · kaleido 0.2
```

**Plotly вдвое тяжелее matplotlib.** «Только HTML-движки» само по себе пакет
не облегчает — оно облегчает его на ~44 МБ (matplotlib + seaborn + wordcloud +
venn) и оставляет 58 МБ plotly. Если цель — ужать, честный вопрос другой:
**должна ли графика вообще быть в базовой установке**, или её место в
extra `[viz]`.

### Три позиции, которые стоит развести в обсуждении

1. **Ужать** — вынести всю графику в `[viz]`. Пользователю, которому надо
   замаскировать колонку, не нужны ни plotly, ни kaleido. Максимальный
   выигрыш по весу, ноль потерь функциональности для тех, кто её ставит.
2. **Сделать полезнее** — один HTML-отчёт на `task_dir` вместо россыпи PNG.
   Это ближе к тому, что делает CORE ценным: не «нарисуй гистограмму», а
   «покажи, что было сделано с данными и с каким результатом». Возможно, вообще
   без библиотек графиков — inline SVG + таблицы дают самодостаточный файл,
   который открывается где угодно и весит килобайты.
3. **Убрать двойной бэкенд** — 16 файлов ведут два пути при одном используемом.
   Это удвоенное тестовое бремя и половина причины, почему 13 модулей не
   покрыты.

Позиции 1 и 3 совместимы и почти бесспорны. Позиция 2 — продуктовая, и её
надо обсуждать, а не реализовывать по умолчанию.

**Мера успеха, которую стоит предложить:** после изменения `pip install
pamola-core` без extras ставит < 300 МБ, а `task_dir` содержит один отчёт,
который можно показать аудитору не открывая Python.

## 3. Что я делал не так — читай до начала работы

Три раза за сессию я строил вывод на правдоподобном, но непроверенном
допущении. Каждый раз проверка занимала минуты и меняла вывод.

| Допущение | Реальность | Как поймалось |
|---|---|---|
| «Мост BEST — публичный контракт, ломать нельзя» | Мост выведен **2026-06-14**, `BRIDGED_OP_CODES = 0` | CD; я успел записать это в ADR и в системный промпт |
| «Удаление 8 зависимостей проверено — ноль ссылок» | Ссылок правда ноль, но `uvicorn` приносил `python-dotenv`, `torch` — `filelock`. Пакет перестал импортироваться | чистая venv, 170 ошибок сборки |
| «`op_base` обвалился 96 % → 59 %» | Я прочитал `.coverage` от **частичного** прогона | сравнение с настоящим отчётом |

Общее: подсчёт ссылок отвечает на вопрос «кто это импортирует», а не «что это
приносило с собой». Отчёт о покрытии отвечает на вопрос «что было в этом
прогоне», а не «что в проекте».

**Практические правила, выведенные из этого:**

- **Никогда не редактируй файлы репозитория через PowerShell.**
  `Get-Content -Raw` + `WriteAllText` читает UTF-8 как cp1251 и записывает
  мохибейк. Я испортил так `.github/workflows/*` и `README.md` — дважды, одним
  и тем же способом. Только Edit/Write.
- Перед удалением зависимости — чистая venv и полный прогон. Статика не
  ответит.
- Перед выводом из отчёта о покрытии — убедись, какой прогон его породил.
- Не обрезай вывод прогона через `tail`, если потом захочешь подушные данные.
  Я обрезал дважды и оба раза потерял то, что было нужно.

## 5. Очередь работ

**Сначала (не заблокировано, высокая отдача):**

1. **`Agg` в `tests/conftest.py`** — причина TD-PC-14 установлена:
   `_tkinter.TclError: Can't find a usable tk.tcl`, matplotlib берёт Tk-бэкенд.
   Отсюда «каждый раз падает другой тест» в `TestDataWriter`. Одна строка.
2. **`tmp_path` вместо фиксированных путей (TD-PC-12)** — тесты пишут 43 файла
   в рабочее дерево, включая **125 МБ модель fastText прямо в дерево пакета**
   (push однажды отклонён GitHub). Сейчас закрыто `.gitignore` — это затычка.
   Настоящее лечение разблокирует `pytest -n auto` и сократит 32-минутный
   прогон.
3. **Шесть воскрешаемых тестов** — F811 в `tests/`, карантин в
   `pyproject.toml` с разбором каждого. Снятие затенения может вскрыть
   настоящие падения; делать отдельным PR со своей проверкой.
4. **Интеграционный контур на паспортах** — `@pytest.mark.integration`,
   ground truth из `*_passport.json` (`direct`/`quasi`/`sensitive` по колонкам).
   Начать с singling-out: он уже есть и принимает ровно `quasi`-поля.
   Исключить из прогона по умолчанию, брать мелкие фикстуры, не `*_10k`.

**Затем:**

5. `eval()` через AST-allowlist; убрать md5/sha1 из псевдонимизации.
6. Векторизация строковых операций на `.str` — замер показывает 1.5–2.3×
   отставания от polars, причина в построчном `.apply`, а не в pandas.
7. Extras (V-1 и Q-03 вместе — они об одном).
8. `SECURITY.md`, Issues, Trusted Publishing (вкладка **Publishing** на
   странице проекта PyPI).

**Перед 1.0 final:** README теряет строку про `--pre` только когда выйдет
финальный релиз — до тех пор плоский `pip install pamola-core` даёт ошибку

## 6. Чего не делать

- **Не мигрировать на polars.** Обоснование в дорожной карте §3; аргумент про
  мост BEST отпал вместе с ADR-PC-02, но два оставшихся в силе, и появился
  третий: pandas — то, чего ждёт внешний пользователь, а четвёртый движок при
  трёх существующих механизмах параллелизма это вес, а не скорость.
- **Не оправдывать решения зависимостью BEST.** Её нет.
- **Не тянуть в CORE control-plane BEST** — оркестрацию, бюджеты, gates,
  evidence packs. И не обещать BEST-grade governance в README.
- **Не добавлять операции** до 1.0. Исключение — singling-out, уже сделано.
- **Не понижать `fail_under`.**

## 7. Мелочи, которые сэкономят время

- Окружение: `.venv` в репозитории содержит torch (старое, 2363 МБ). Для
  честного замера веса собирай новое из текущего `pyproject.toml`.
- `PAMOLA_PROJECT_ROOT` выставлена на машине и указывает на HHR. Корневой
  `conftest.py` её снимает, но при ручных запусках вне pytest помни о ней.
- Полный прогон ~32 мин. Запускай фоном и работай параллельно.
- Сообщения коммитов пиши через файл (`git commit -F`), а не heredoc:
  PowerShell ломает кавычки. И `Out-File -Encoding ascii`, иначе BOM попадёт
  в тему коммита.
- `gh pr list --jq` с интерполяцией строк в PowerShell не работает — кавычки
  съедаются. Используй `| ConvertFrom-Json`.

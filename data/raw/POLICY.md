# Data Publication Policy — `data/raw/`

**Status:** normative for this repository.
**Last reviewed:** 2026-08-16.

This file states, in one place, what may appear in `data/raw/` of the public
PAMOLA repository and why. `README.md` in this directory describes the
datasets; this file describes the *rule*.

---

## 1. Everything published here is synthetic

**All datasets under `data/raw/` are fully synthetic. They contain no real
personal information (PII) and no protected health information (PHI).**

- Artificially generated for testing, validation, and demonstration.
- Not collected from any external source.
- Not derived from, sampled from, or conditioned on any real customer,
  employee, or patient dataset.
- Any resemblance to actual persons, organizations, or events is coincidental.

Generation uses [Faker](https://faker.readthedocs.io/) for identity-shaped
fields, domain-specific generators for realistic medical codes and transaction
patterns, and statistical distributions chosen to match real-world *shapes*
without using real-world *records*.

*This notice is provided for transparency, not as legal advice.*

## 2. Every dataset carries a passport

Each file ships a `*_passport.json` recording at minimum the dataset name,
record count, encoding, generation timestamp, and the
`direct` / `quasi` / `sensitive` privacy categorisation of every column.

The passport is what makes the claim in §1 *auditable* rather than merely
asserted. **A dataset without a passport must not be committed.**

Where the generator itself is committed (e.g.
`med_rare_lab/generate_med_rare_lab.py`, `bank_txs/generate_bank_txs_v2.py`),
it is part of the provenance record and should be kept in sync with the data.

## 3. Datasets are fingerprinted

Generated datasets carry intentional **synthetic fingerprints** — patterns in
value distributions and markers in identifier fields, embedded at generation
time.

Fingerprints exist to:
1. **Prevent misrepresentation** — detect a synthetic dataset being passed off
   as real;
2. **Enable lineage tracking** — trace data origin through processing
   pipelines;
3. **Support audit scenarios** — demonstrate provenance in compliance review.

Fingerprints contain no real personal data, track nothing, and transmit
nothing. They do not affect testing validity. **Do not strip them** when
deriving smaller fixtures from a published dataset.

## 4. Third-party corpora are never committed

Real-world reference corpora used in PAMOLA research — MIMIC-III, the Enron
email corpus, NYC Taxi Trips, UCI Adult, IEEE-CIS Fraud Detection, Synthea,
ai4privacy, NVIDIA Nemotron-PII, BERKA, CFPB, folktables/ACS, and similar —
live **only** in the private local research workspace (`_DATARAW`).

**They must never be copied into this repository**, in whole or in part,
regardless of their individual licences. This repo publishes PAMOLA-generated
synthetic families and nothing else.

If a demo or test genuinely needs a third-party corpus, reference it by URL
and a download script. Never vendor the bytes.

## 5. Adding data — checklist

Before committing anything under `data/raw/`:

- [ ] Generated by a PAMOLA generator; no real records used as input
- [ ] `*_passport.json` present, with privacy categorisation filled in
- [ ] A `readme.md` in the dataset directory describing schema and intent
- [ ] Fingerprints intact
- [ ] Licence terms for the dataset are stated and compatible with this
      repository's BSD-3-Clause licence
- [ ] Size justified — see §6
- [ ] Committed **on its own**, in a data-scoped commit. The current corpus
      entered on 2026-01-10 inside an unrelated README commit, which is why
      its provenance material is easy to miss.

## 6. Size and surface

Synthetic and safe is not the same as *worth publishing*. Full-size datasets
cost every contributor and every CI checkout a large clone, and realistic
data invites misuse even when fingerprinted.

Preference, smallest first:

1. **Small fixtures in-repo** — the 50–2 000 row files that the test suite
   actually loads, plus dictionaries. These are cheap and belong here.
2. **Full-size demo datasets out-of-repo** — release assets or a companion
   data repository, fetched on demand.
3. **Passports, readmes, generators always in-repo**, regardless of where the
   bytes live. Provenance must never depend on an external fetch.
